# Merovingian 1.0.0

Draft release notes. Version approved; not yet published.

## New operating model

Merovingian now exposes an authenticated Catalog and immutable personal Journal.
The purpose graph defines access to plugins, tools and repositories. Tenant setup
skills install capabilities through native marketplaces with human approval;
member machines authenticate with individual SurrealDB credentials.

- Catalog returns the authorized slice, tenant instructions, plugin bindings and
  deterministic content revision. Repository intent is distinct from verified access.
- Journal supports append/list, server-stamped authorship, references to earlier
  entries, and author/admin visibility. Corrections use new entries, never edits.
- GitHub deployment reconciles declared repository access and review protections
  using an explicitly approved plan revision, including scoped administrative bypass.
- Administrative history export/verification preserves retired data for restricted
  consultation. Existing historical tables become inaccessible to product identities.

## Breaking changes and migration

Workspace build/emitters, the HTTP build service, library update, plugin sync,
namespace add, inbox/decision commands and MCPs, and console inbox are removed.
There is no supported legacy runtime track. Init creates graph/configuration
scaffolding without generated skills or client workspaces.

Replace local library references with explicit plugin references, remove top-level
agent metadata, and move general instructions to `ambient.instructions`. Publish
required tenant capabilities before deploying the new graph. Configure Catalog and
Journal in each client's private MCP settings; do not give members administrative
credentials. GitHub/email/Slack profile identifiers remain administratively managed.

Before upgrading an existing tenant, follow the [history and cutover guide](../guides/history-and-cutover.md).
Stop old writers, preserve the final historical snapshot, and confirm a complete
operational backup. The historical archive alone is not a full database backup.
Do not run the old deploy after cutover: it can restore retired permissions.

## Boundaries

Initial client target is macOS: Claude Code terminal and desktop Code tab, and Codex
terminal and desktop. Native acceptance evidence and remaining gates are recorded in
[candidate review](../testing/release-candidate.md). Claude chat/Cowork are outside this matrix.

Setup diagnostics are on demand. The catalog does not distribute third-party secrets
or prove local installation. Journal has no pending queue, edit/delete, or automatic
import of historical decisions/frictions. Historical triage remains post-release work.

The administrative governance plugin has its own version, 0.6.0, and publication path.
