# Merovingian 1.0.1

Patch release for operator diagnostics, safe deployment planning and authentication.

- Initial real-tenant provisioning rejects signing keys shorter than 32 characters
  after excluding surrounding whitespace, and rejects the public development key
  even with surrounding whitespace. Existing identity keys are not rotated.
- Deployment planning distinguishes empty databases from incomplete state. Missing
  structural tables, duplicate/wrong-tenant configuration, and surviving records
  without configuration stop planning with actionable diagnostics.
- A new configuration appears as a creation rather than an update. First provisioning
  writes configuration first so an interrupted structural write can be retried.
- Login and password-management errors report sanitized target/configuration sources,
  distinguish connection/read/write failures, and preserve schema-drift diagnostics.
  Cleanup errors cannot replace those diagnostics or turn a successful password write
  into a reported failure.
- Catalog authentication classifies rejected credentials consistently on SurrealDB
  3.0.1 and 3.2.0, keeping missing tenant/schema errors distinct.

Upgrade the CLI with `bun add -g @supernova-labs/merovingian@1.0.1`, then verify
`merovingian --version`. This patch does not require re-keying or a production database
migration. Independently pinned MCP runtimes and governance plugins do not update
when the global CLI is upgraded.

Implementation and validation: [PR #42](https://github.com/supernova-labs/merovingian/pull/42).
